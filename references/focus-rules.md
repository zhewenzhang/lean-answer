# 聚焦规则

文章的核心机制是**生成—验证不对称**：生成已近零成本，消化（验证、整合、判断）仍需稀缺注意力。冗余输出的代价不是「多读几行」，而是「议程被答案占满，无法提出该问的问题」。本文件把对策拆成两侧。

## 1 个人工作方式（你侧）

- **单主线**：一次只推进一个目标。写好、验完、收口，再开下一个。
- **闭环权**：只开启自己能验收的环。开环的人负责闭环（文章：one person closes the loop），否则验证成本会转移给未来的自己。
- **注意力预算**：每轮 ≤1 图 + ≤1 表 + ≤500 字；每天最多 3 个主题并行，超了就排队。
- **一层做透再上移**：一件事达到可验收状态（判据通过）才开第二件。同时开三件的结果是三件都停在 70%。
- **上下文卫生**：每 5–8 轮把结论压成**决策档**（结论 / 未决 / 下一步），后续只引用档，不复述原文。长会话的价值在档，不在历史长度。

## 2 协作协议（双方）

- **提问契约**：一次一问，并标明「这轮只要 X」。三个问题分三轮，不是一轮三问。
- **输出契约**：结论 → 一个动作 → 一句阻断项（若有）。不加顺手建议。
- **拆轮**：第二个主题一律下一轮。`另外 / 顺便 / 附带 / 也可以考虑` 出现两次以上即为夹带信号。
- **议程保留**：每轮最多 1 个下一步。把下一轮的空间留给你提问，而不是由我把答案排满。
- **换题即换会话**：不同主题不共用上下文，避免旧判断污染新判断。
- **超载声明**：我若判断本轮承载不了，必须显式砍到 1 条主线，并说明砍掉了什么、留到哪一轮。

## 3 与文章机制的对应

| 文章机制 | 本规则的落点 |
|---|---|
| 生成—验证不对称 | 输出上限（字数/图/表）+ 每轮 1 个下一步 |
| 生成可见、消化不可见 | 决策档压缩，把消化结果留下、过程丢掉 |
| 议程从「问题」变为「答案」 | 每轮只给 1 个下一步，剩余空间留给你 |
| 一人多能 vs 一脑多肢 | 闭环权：开环者必须能验收并承担后果 |
