# 三档严格度：lite / standard / audit

同一个 skill 面对三种场景，代价与收益不同。默认 standard；用户一句话就能换档。

## 什么时候用哪档

| 场景 | 档位 | 判断信号 |
|---|---|---|
| 我自己看，越快越好 | lite | 「简一点」「别解释」「给个结论」 |
| 发给同事、写进汇报 | standard | 默认，无需说明 |
| 给甲方、要过审、团队规范检查 | audit | 「要交出去」「要合规」「查一下有没有 AI 味」 |

## lite

只做减法，不动句式与标点。

- 删：开场客套、收尾邀约、复述题目、重复总结、过程流水账。
- 保留：所有事实、数字、判断、风险、下一步。
- 不查：黑名单句式、引号规范、数字空格、篇幅上限。
- 理由：内部对话里「值得注意的是」不构成问题，为它改写反而拖慢响应。

## standard

全套规则生效，发送前过闸。这是默认档。

- 跑 `gate.py`：结构（开场/收尾/平行方案/篇幅/聚焦）+ 表达（引号/空格/句式/抽象词）。
- ERROR 必须改写；WARN 自行判断。
- 改写别人稿件时跑 `deai.py`，出改动表。

## audit

standard 之上加一份可交付报告，用于对外交付或团队抽查。

```bash
python scripts/audit.py 稿件.md                    # Markdown 报告
python scripts/audit.py 稿件.md --html 报告.html    # 另出 HTML
python scripts/audit.py 资料夹/ --recursive         # 批量汇总
```

报告内容：综合得分（100 − 12×ERROR − 3×WARN，最低 0）、逐条违规的位置、问题、改法。评分口径写死在脚本里，改口径必须同步改本节。

| 得分 | 结论 |
|---|---|
| 90-100 | 可直接对外 |
| 70-89 | 需修订后对外 |
| 0-69 | 重写 |

audit 档不追求短。报告本身就是交付物，正文宁可多留证据。

## 换档的边界

- 用户明确说档位 → 直接照做，不再问。
- 用户没说但明显是对外交付（提到甲方、发布、汇报） → 用 standard，并在结尾一句提示「要 audit 报告可以再跑一次」。
- 高后果内容（医疗、法律、合同、安全） → 至少 standard，且规则冲突时安全优先。
- 无论哪档，不替用户升华、不编造感受与事实这条永不放宽。
